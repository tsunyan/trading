# 実発注台帳の損益レポート

2026-10-04。専用の実発注台帳に保存した照合済みの記録から、損益とリスクの余裕を表示する
読取専用のCLIを追加しました。資格情報・HTTP・状態の変更はありません。

```powershell
uv run python -m trading.live_report --directory runs/live-orders --read-control-directory runs/account-read-control --scope <scope> --history 24
```

## 表示する内容

- 口座: 最後の口座証拠の時刻・残高・評価額・未決済スワップ・拘束証拠金・余力・建玉
- リスクの余裕: 開始残高からの損失と損失上限までの残り、ピークからの下落率とその上限、
  損失による新規停止の有無
- 注文: 状態、売買、新規/決済、数量、約定数量、平均約定価格、手数料、実現損益、決済スワップ
- 合計: 実現損益・手数料・決済スワップと、その差し引き（実現損益＋スワップ−手数料）
- 評価額の推移: 直近`--history`件（既定24、最大1000）の照合済み口座証拠の時刻と評価額

## 執行コスト（スリッページ）

`order_runtime submit --dispatch-log runs/live-orders/dispatch.jsonl`で、受付された送信ごとに確認した
実行内容のSHA-256と気配を1行ずつ記録できます。`live_report --dispatch-log`（`live_dashboard`も同じ）は
これを約定と突き合わせ、注文ごとに1通貨あたりのスリッページ（買いは平均約定価格−確認時の売気配、
売りは確認時の買気配−平均約定価格。正の値は確認時の気配より不利）と、合計の執行コストを表示します。
記録のない注文は計算しません。ログが壊れた行は無視します。台帳の記録は変えません。

## 約定明細のCSV

`--executions-csv runs/live-orders/executions.csv`で、照合済みの全約定（時刻・注文・注文ID・約定ID・建玉ID・
売買・新規/決済・数量・価格・手数料・損益・決済スワップ）を時刻順にCSVへ書き出します。業者の約定履歴と
1行ずつ突き合わせるための出力です。既存のファイルは上書きしません。

金額はすべて台帳の照合済み証拠の値です。業者の取引報告書との照合は行っていないため、
出力の`broker_verified`は常に`false`です。手数料は支払いを正の値で表します。
