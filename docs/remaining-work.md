# FX実用化の残件

更新: 2026-10-05。`feat/live-remaining-gaps`のClaude最終コミット`d9b23ec`と、その後のCodexの変更を対象に整理しました。
過去のレビューや工程別記録にある「未実装」は当時の状態です。現在の残件はこの一覧を参照してください。

## 今回進めたもの

空き容量の診断を実際の送信経路へ接続しました。実発注台帳・POST制御・GET制御の保存先を個別に検査し、
どれかの空きが1GiB未満、または取得不能なら、新規・決済・取消を送信しません。
発注用キー読込前、読込後、POST待機後、HTTP送信直前に既存の検査経路から再確認します。
停止中の対象限定取消も同じ検査を通ります。[状態診断](live-doctor.md)も同じ判定を使います。

POST待機後の拒否は注文を未送信のまま維持します。claim取得後、HTTP前の拒否は、既存の未送信処理で
新規・決済を`ABANDONED`へ、取消を取得した証拠に対応する状態へ戻し、POST枠を完了します。
未送信の保存に失敗した場合は、従来どおり結果不明として停止を保持します。
容量検査は空き領域の予約ではないため、検査後の書込み成功は保証しません。
同期・監視・現金台帳だけが別ドライブにある場合の容量検査は、引き続き残件です。

容量検査を実発注台帳の実装SHA-256の対象に加えました。実発注側のコード更新後は、現在のコードで
再承認する既存の手順が必要です。ペーパー観測の固定コアは変更していません。

PR #17のレビューで残っていた同期CLIの拒否理由表示も修正しました。`JournalError`の固定コードを
表示対象に加え、`review-delivery`が`journal_review_not_required`などを返す場合も理由を確認できます。
表示は従来と同じ1〜64文字の英小文字・数字・下線に限り、任意の例外本文は表示しません。

旧資料の不在解消・送信ログ・スワップの記述も現在の実装に合わせました。
稼働中のSMAペーパー観測では固定コアのSHA-256がmanifestと一致し、正常終了・遅延なしを読み取り確認しました。
観測口座やタスクの定義を変更する工程はありません。

## 口座なしで進められる実装

| 優先 | 残件 | 完了条件 |
| --- | --- | --- |
| P1 | 取消の結果不明で注文が有効なまま残る場合の解消 | 取消が遅れて反映される場合・部分約定・全量約定との競合を含め、証拠と明示承認により元のclaimを解消する。再送・旧取消許可の再利用を拒否し、台帳とPOSTのcommit前後で終了しても安全に完了できること |
| P1 | 同期・監視・現金台帳の別ドライブの空き容量 | 登録済みの元の保存先を検査し、診断と送信前検査を一致させる。検査で同期を開始したり、未登録ストアを作成したりしないこと |
| P2 | 旧形式のGET claim・同期の結果不明の復旧 | 元の所有者不在と紐付けを検証する明示移行・復旧。履歴欠損やロックファイル欠落を時間経過で解除しないこと |
| P2 | 長期保存に比例する検査時間 | 実運用の量で再測定し、必要なら完全性の検査を維持した改善を行う。PR #15の全アーカイブ検証は測定を理由に維持した設計であり、単に削除しない |

取消の非終端復旧は、注文が今も有効だというGETだけで「取消が届かなかった」と扱わない設計が必要です。
まず保存済み取消claimと完全履歴の契約を定め、障害試験を用意してから送信経路へ接続します。

## 実口座・運用者の準備が必要なもの

| 残件 | 必要なもの・完了条件 |
| --- | --- |
| 読取受入・全口座照合 | 口座本人性、キーの権限、開始残高・建玉・全入出金・注文約定履歴、REST/WebSocketの欠落、業者の評価額・証拠金・丸め式を実資料で確認する。Windowsストアとキー失効・復旧も実機検証する |
| 本口座用の同期・監視タスク設置 | 元のGET/POST制御と台帳へ登録し、長時間運転、切断・再接続・通知・独立監視の停止を実環境で確認する |
| 小額の受入試行 | [試行手順](live-first-trial.md)に従い、資金・損失・数量上限を固定し、手動送信後の注文・約定・口座会計が業者履歴と一致すること |
| 実運用に昇格できる戦略 | 仮説・コード・条件を凍結し、事前固定したforward OOS条件を満たして`judge`が合格を記録する。現在のSMA観測は探索用途であり、既存口座を後から合格候補に読み替えない |
| 自動送信 | [設計案](live-autonomy-proposal.md)に対する実装可否と期限・日次回数・損失上限の判断。小額の手動受入を先に終えるかも決める |

日本株、複数銘柄・複数戦略は[ロードマップ](roadmap.md)の後続工程です。
現段階のFX受入の完了条件には含めません。
