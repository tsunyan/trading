# 約定からの建玉会計

2026-10-02。現金台帳に、宣言した開始建玉と個別約定から保有数量・加重平均取得価格・
決済損益を再構築する機能を追加しました。建玉の検証と現金仕訳の保存を同じトランザクションで行います。
実口座の建玉計算・丸め規則や、全履歴の完全性を証明するものではありません。

## 開始建玉の宣言

新しい台帳を作るとき、`OpeningCash.position_basis` を明示します。
空の `positions=()` も「境界時点に建玉なし」という運用者の宣言です。
[明細証拠による入出金会計](cash-transfers.md)を明示するversion 3でも、この開始建玉を併用できます。
現在のREST建玉を自動で開始建玉へ取り込む処理はありません。

```python
from datetime import UTC, datetime
from pathlib import Path

from trading.execution_cash_book import ExecutionCashBook, OpeningCash
from trading.execution_positions import OpeningPosition, PositionBasis

book = ExecutionCashBook.create(
    Path("runs/declared-position-book"),
    "declared-account-scope",
    OpeningCash(
        balance="1000000",
        cutoff=datetime(2026, 10, 2, tzinfo=UTC),
        position_basis=PositionBasis(
            positions=(
                OpeningPosition(position_id=401, side="BUY", units=400, average_price="150"),
            ),
            realized_pnl_tolerance="0",
        ),
    ),
)
```

この宣言を含む新規台帳はversion 2です。開始建玉・損益許容差・版は初期ハッシュに含めます。
開始建玉は最大1,000件、IDの重複を拒否します。数量は建玉ごとに10^12通貨まで、
取得価格は10^18円まで・小数8桁以内、開始宣言の保存本文は1MBまでです。
境界以前の約定は計上せず、開始建玉の取得に使った約定を再計上しないことは別途確認が必要です。

`position_basis` を省略した現金専用のversion 1は、既存の保存形式と初期ハッシュを維持します。
その台帳では建玉なしと推測せず、建玉照合を拒否します。自動移行や開始建玉の追記・上書きはありません。
version 2の台帳を古い実装で開くことはできません。

## 個別約定の再構築と計上拒否

計上済みと新規の個別約定を約定日時順に再構築します。保存時の約定ID順や到着順は使いません。
複数の新規約定が同じ日時・同じ建玉に属する場合も、加重平均は正確に計算できます。
同じ日時・同じ建玉で新規と決済が混在する場合は、前後関係を証明できないため拒否します。
約定IDの大小から経済上の順序を推測しません。

- 新規は同方向の数量と取得原価を加算します。新規の決済損益・決済スワップは0を要求します。
- 決済は指定した建玉への割当、反対方向、保有数量と注文数量の上限を確認します。
  決済損益は、買い建玉なら「決済価格−平均取得価格」、売り建玉ならその逆に決済数量を掛けます。
- 部分決済後も残った数量の平均取得価格を維持します。全決済後の建玉ID再利用は未対応として拒否します。
- 過去の新規約定が遅れて到着した場合も再構築します。既計上の決済損益が合わなくなる追記は拒否します。

取得原価と平均価格は分数で計算し、呼出し元のDecimal精度に依存しません。
表示用の小数8桁はhalf-evenで丸めますが、次の計算には分数を使います。
分子・分母は4,096bitまでとし、超えた場合は丸めず計上を拒否します。

決済損益の比較は既定で完全一致です。`realized_pnl_tolerance` を開始宣言に含めると、
約定ごとに0〜1円・小数8桁以内の許容差を明示できます。業者の実際の丸め規則は未検証です。
現金にはRESTと通知で一致した損益を計上し、計算した損益との差を
`position_pnl_rounding_difference_exact` に分数で表示します。差を追加仕訳で補正しません。

不明な建玉への決済、超過決済、方向矛盾、損益不一致などは、証拠・約定・現金仕訳の書込み前に拒否します。
最後の正常な残高と建玉は維持します。過去の不足約定も含めた新しい照合バッチで再検証はできますが、
許容差や開始宣言を自動で変更しません。既存の約定ID・注文意図の矛盾による永続停止は引き続き適用します。

## 保存・再起動・同期経路

建玉の状態は、変更可能な別テーブルに保存せず、開始宣言と検証済み約定から毎回再構築します。
読み取り時も現金仕訳・証拠・ハッシュ連鎖と建玉損益を検査します。
数量・平均価格・損益は`apply`の結果と`snapshot`に含まれ、分数は分子・分母の文字列で返します。

現金と建玉は同じ末尾ハッシュを参照します。SQL書込み失敗では新しい証拠・約定・仕訳をまとめてROLLBACKし、
commit直後に終了しても、再起動時はその記録から建玉を復元します。同じ約定の再確認で数量を加算しません。
独立した可変の建玉残高を修復する処理はありません。

[同期モニターからの計上](execution-cash-sync.md)にも、この台帳をそのまま明示できます。
捕捉・世代・revision・鮮度の確認を行った後、建玉検証を含む計上を実行します。
結果の`position_accounting_applied=true`は、この開始宣言と個別約定に対するローカル計算だけを表します。
口座全体の会計完了や発注許可には変換しません。

## REST建玉との比較

```python
from decimal import Decimal

comparison = book.compare_positions(
    reader.collect_account(),
    price_tolerance_jpy=Decimal("0"),
)
```

建玉ID・方向・数量・平均取得価格を比較し、不足・予期しない建玉・内容差を返します。
比べるREST観測が開始境界や最新計上約定より古い場合、重複ID、未来の建玉時刻、不正な観測を拒否します。
価格許容差は既定0円、明示指定の上限0.01円です。表示用平均価格を正しい取得原価として取り込みません。
REST建玉と差があっても、台帳の数量・価格・開始宣言を書き換えません。

含み損益・未決済スワップ・注文による拘束数量・証拠金計算は別の工程です。
建玉比較が一致しても、開始境界・失った履歴・全入出金・外部操作・本人性・原子的な口座観測の確認は残り、
`complete=false`、`live_enabled=false` を維持します。
