# 採用構成と進め方

調査日: 2026-09-22。日本居住の個人利用を前提に、FXを先に稼働検証し、日本株へ広げます。

## 証券会社・データ提供元

| 用途 | 採用先 | 選定理由と条件 |
| --- | --- | --- |
| FXの初期検証 | GMOコイン・外国為替FX | 公開APIから認証不要で過去足と現在のBid/Askを取得可能。まずローカル模擬売買で利用する |
| 将来のFX発注 | GMOコインを第一候補 | 同じ価格配信元のPrivate APIへ接続できる。口座開設・APIキー取得・発注実装は別工程 |
| 日本株の将来の発注 | 三菱UFJ eスマート証券・kabuステーションAPI | 個人向け自動発注APIを公開。Professional以上が必要。Windows上でkabuステーションを起動して利用 |
| 日本株の過去データ | J-Quants API V2 | JPX系の公式ヒストリカルデータ。契約プラン・取得期間を決めて導入する |
| FXの代替候補 | OANDA証券 | APIのデモ利用にも条件があり、初期の口座不要検証には採用しない |

GMOのAPI手数料は約定金額の0.002%。初回キー作成後30日の免除はバックテストには適用せず、
通常の料率を設定しました。USD/JPYのAPI取引ルールは調査時点で新規最小100通貨、
数量刻み1通貨。模擬売買開始時に公開APIのルールと設定の整合を再確認します。
スプレッドと滑りは変動するため、設定値は研究用の仮定です。

OANDAは公式FAQで、本番口座、Gold、プロコース、残高25万円以上などがデモAPIにも必要と
案内しています。既に条件を満たす口座がある場合は代替になり得ます。
今回、口座開設・入金・有料契約は行っていません。

## システム

```text
GMO公開API / 将来のJ-Quants取得
               |
          CSV / Parquet
               |
     入力検証・戦略判定・数量決定
          /                 \
 Backtrader                FX paper-step
 次足で模擬約定            現在Bid/Askで模擬約定
          |                 |
 資産曲線・注文・レポート   SQLiteの状態・履歴
```

初期はWindows上の単一Pythonプロセスとローカルファイルで運用します。
バックテスト用データはParquet、時系列の実行履歴はSQLite、設定はTOMLです。
CLIで再現可能にし、Python環境はuvとロックファイルで固定します。
Web UI、クラウド、Docker、キュー、別DBサーバーは初期には導入しません。

共通化するのは入力形式、戦略判定、数量決定、コスト設定です。
バックテストとフォワード模擬売買は約定時点が異なるため、執行処理は分けます。
SQLiteトランザクション内で状態とイベントを同時に記録し、重複実行を防ぎます。
本番運用へ進む段階では、注文IDと実口座の照合、接続復帰、取消・失効・部分約定への対応が必要です。

## 初期パラメータ

- FX: USD/JPY、1時間足、12/48本移動平均、仮想元本100万円、1回の配分20%。
- 日本株: 日足、10/30本移動平均、仮想元本100万円、1回の配分30%、100株単位。
- 両方: 買い持ち/ノーポジション。買い増しなし。ピークから5%下落を検出すると停止。
- 日本株の7203は入力例。FX・株とも銘柄や戦略の収益性を推奨するものではありません。

これらはテスト用の設定です。値幅、取引コスト、出来高などの検証結果から変更します。
長期保有のFXスワップ、日本株の配当・分割処理は未実装なので、成績評価前に補います。

## 次の実装順

1. FX: 数か月以上のデータを保存し、学習・検証期間を時系列で分けて比較する。
2. FX: スワップを追加し、スプレッド拡大や滑りを増やした条件でも検証する。
3. FX: paper-stepを定期起動する運用、障害通知、観測記録の長期保存を整備する。
4. 日本株: J-Quants契約とデータ仕様を確定し、企業行動・取引カレンダーを処理する。
5. 日本株: kabuステーションの気配を読むアダプターとローカル模擬売買を接続する。
6. 実発注が必要になった段階で、口座に合わせた発注・照合・停止処理を別途実装する。

証券会社の検証環境への接続テストと、実際の相場を使うフォワード検証は別の工程として扱います。
