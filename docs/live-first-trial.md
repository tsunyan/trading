# 小額の受入試行の手順

2026-10-04作成。GMO口座の準備後に、実口座で最初に行う小額の試行の手順と合格条件です。
コードの試験合格だけでは実運用の完了としません（[計画](fx-practical-plan.md)）。
この文書の手順はまだ実口座で実行していません。実行後に結果と気づいた点を追記してください。

## 前提

- 口座の資金は試行で失ってよい額に限ります。台帳の方針（`AccountPolicy`）の`max_order_notional`・
  `max_gross_notional`・`max_loss_jpy`は、その額に合わせて小さく設定します。
- 手動発注や別アプリなど、台帳の外から口座を操作しません（`external-writers-paused`）。
- 試行中は画面と業者の取引履歴を並べて確認できる状態にします。

## 1. 読取の受入

1. 読取専用キーを保存し（[キー保管](credential-store.md)）、GET制御・POST制御を作ります。
2. [業者の取引ルールと照合](live-rules.md)して台帳の設定を決め、台帳を作ります（[手順書](live-setup.md)）。
3. 同期・監視を初期化して台帳に登録し、同期と監視タスクを動かします。
4. [読取の証拠](live-acceptance.md)を`account_baseline`と`read_acceptance`で保存します。

確認すること:

- 証拠ファイルの残高・建玉・有効注文が業者画面と一致する。
- 建玉・有効注文が0件の口座で、走査が空のページで正常に終わる（0件応答の形式は未確認です）。
- `live_doctor`で、許可と口座証拠以外の項目が合格する。

## 2. 有効化

1. [口座証拠を更新](live-account.md)します。
2. 本人性・業者ルール・履歴の資料を用意し、[承認ファイル](live-acceptance.md)を作って有効化します。
   有効期間は試行に必要な長さ（例: 24時間）にします。
3. `live_doctor`がすべて合格することを確認します。

## 3. 新規と決済の往復

1. 最小数量の新規の注文意図（成行・価格保護つき）を用意し、`live_setup prepare`で準備します。
   戦略の提案を使う場合は`live_cycle --prepare`で準備します。
2. `order_runtime context`の本文（数量・売買・価格保護）を確認し、`order_runtime submit`で送ります。
3. [受付済み注文のGET照合](live-order-sync.md)で`FILLED`にし、口座証拠を更新します。
   建玉がある間は`--valuation-tolerance`を小さい値（例: 0.05）で指定します。
4. `live_cycle --flatten --prepare`で決済を作り、同じく送信・照合・口座証拠の更新をします。

確認すること:

- 業者の約定履歴（約定ID・数量・価格・手数料・損益）と、[損益レポート](live-report.md)の各注文が一致する。
- 決済後の残高が、台帳が約定から再計算した残高と一致する（口座証拠の更新が`balance_mismatch`なく通る）。
- 建玉がある間の評価額と業者の評価額の差が、指定した許容幅に収まる。差が大きい場合は
  業者の評価方法（どの気配で評価しているか）を記録します。
- 新規と決済の手数料・スワップの丸めを記録します。

## 4. 障害の確認（任意）

- 監視タスクを止めて`live_doctor`と送信が`sync_and_watchdog`で拒否されることを確かめます。
- `live_setup stop`で台帳を止め、[明示再開](order-restart.md)の手順で再開できることを確かめます。
  承認は`live_acceptance restart-approval`で作ります。

結果不明の送信を意図的に起こす試験は、実口座では行いません。

## 合格条件

- 1〜3の確認がすべて一致し、台帳の停止・結果不明が一度も起きない。
- 業者の取引報告書の数値と、損益レポートの合計（実現損益・手数料・スワップ）が一致する。
- 試行で分かった業者の仕様（0件応答の形式、評価方法、丸め、MARKET注文の受付応答の形）を
  関係する文書に追記した。

不一致があれば台帳を停止し、原因を記録してから進めます。
